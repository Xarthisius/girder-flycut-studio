# `.eslintrc.json` notes

The formatting rules are **on**. They were switched off from Phase 1 to Phase 3
because the build derived the dashboard's sources from `config_builder/static/`
by matching literal source text — one needle spanned a line break and its
indentation — so reformatting broke the build. Decision 3 settled that the
plugin owns its sources; Phase 4a deleted the generator, and the deferred
`eslint --fix` ran in the same commit: 1,279 findings, all auto-fixable.

The minified bundle was byte-identical before and after, which is what you would
expect from a whitespace-only change and worth having checked.

One rule stays off, permanently:

**`promise/no-native`** exists so Girder's Backbone code uses jQuery deferreds
from `restRequest`. The builder is plain DOM code with its own `fetch` shim,
where native promises are correct.

Two `no-new-func` / `no-return-assign` disables survive in
`tests/workflow.cjs` and `tests/complete_workflow.cjs`. Those suites still slice
`renderHome`, `canLeave`, `configure` and the submit flow out of `main.js` and
eval them, because that code is DOM orchestration over the shell's closure and
cannot be imported until it becomes Backbone views. That is the remainder of
issue D1.

Those slice boundaries have now broken three times in four phases — on
de-indentation in Phase 2, on the move in Phase 3, and on `arrow-parens` here.
Each break was loud rather than silent, but the pattern is the argument for
finishing D1 rather than maintaining the boundaries.

`test/browser/**` is configured with both the `node` and `browser` environments.
It is a Node script, but the bodies of `page.evaluate()` callbacks are
serialised and run inside the page, so `document` and `getComputedStyle` are
genuine globals there.
