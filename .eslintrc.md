# Why `.eslintrc.json` switches off the formatting rules

`@girder`'s config is semistandard: 4-space indent, single quotes, spacing rules.
The browser sources here are written in a denser style and violate it 1,445 times,
every one of them auto-fixable. Running `eslint --fix` is one command, so the
rules are off for a reason rather than out of reluctance:

**The source generator matches literal source text.** It rewires the builder by
substituting exact strings out of `config_builder/static/app.js`, and one needle
spans a line break *and its indentation*:

```js
app = sub(app, 'renderAutocomplete();\n    fillSelect', ...);
```

Reformatting app.js moves that text, the substitution stops matching, and the
build fails loudly.

Phase 2 was expected to remove these needles by retiring `build_dashboard.py`.
It did not, and the expectation was wrong: the needles exist because the markup
is *derived from* `config_builder/static/index.html`, not because a Python
script did the deriving. Porting the generator to JavaScript moved them, it did
not delete them.

Decision 3 has since been answered: the plugin takes ownership of its markup and
`config_builder/static/` is deleted in Phase 4. The substitutions go with it, and
**the formatting pass runs in that same phase** -- one `eslint --fix`, with
nothing left matching the source text it rewrites.

Until then this config enforces the rules that catch defects and stays quiet
about the ones that only move whitespace.

`promise/no-native` is off for a different reason, and permanently: it exists so
Girder's Backbone code uses jQuery deferreds from `restRequest`. The builder is
plain DOM code with its own `fetch` shim, where native promises are correct.

Tracked as issue C5 and Decision 3 in `docs/CONVERSION_PLAN.md`.
